## Children

For a digest, call the native Agent tool with `run_in_background: true`,
`subagent_type: "general-purpose"`, and `prompt: "Follow <DIGEST_PROMPT>"`.
Pass the rendered file path alone, not the producer artifact or parent history.
Wait for its native completion; an error or missing verdict blocks advancement.

For local proposal, follow the Claude adversarial-proposal skill's four-round
workflow using native Agent and SendMessage. Create fresh A and B with disjoint
instructions and the same rendered operator constraints/frame challenge.
Do not send either proposal to the other proposer. After both complete,
create fresh C with only the designated synthesis inputs. Deliver independent
review feedback to the original A/B agents and join their native completions.
Never emulate child work sequentially in the parent or in a shell CLI.

Model selection follows the qualified native host/child configuration. Native
Claude children share the host's authority; do not describe them as contained
worker panes. Approvals are individual native approvals, never blanket shell
or generic Forge-prefix authority.

## Gated Local QA

First apply all local-QA prerequisites in `workflow-routes.md`. Confirm native
live-QA tool access for the child configuration, not merely that Agent exists.
An unavailable capability blocks fallback; do not run QA in the parent context.

Only under the canonical local build QA fallback, hold the infra lock, use
`local-render --stage qa` (or qa-retry) before pending creation, and execute
the protected Claude adversarial-qa skill with native Agent/SendMessage.
Carry the rendered constraints and `.dev/qa/{slug}` output paths into isolated
child inputs. Join all children, close the local pending with log-response,
release the lock and run the digest. Never emit a worker callback for local QA.
